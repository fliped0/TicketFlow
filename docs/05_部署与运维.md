## 1. 已验证部署方式

Windows、Java 17、Maven 3.9.12、MySQL 8.0.45；PowerShell 7.4+。参照仓库 README 完成本地初始化，然后运行 `pwsh -File scripts/test.ps1` 与 `pwsh -File scripts/run.ps1`。应用包为 backend/target/ticketflow-0.1.0-SNAPSHOT.jar；可复制到独立目录运行，不需要源码或个人绝对路径。

独立启动需设置 TF_DB_HOST、TF_DB_PORT、TF_DB_NAME、TF_DB_USER、TF_DB_PASSWORD、TF_JWT_PRIVATE_KEY、TF_JWT_PUBLIC_KEY；TF_PORT 默认 8080。RSA 私钥为 PKCS#8、公钥为 X.509，至少 2048 位且必须配对。凭据通过环境配置注入，不写入仓库；生产管理员通过 TF_ADMIN_USERNAME / TF_ADMIN_PASSWORD 首次初始化后移除变量。

实验使用专用 ticketflow_test / tf_test、临时生成的 RSA 密钥、随机端口及复制后的 jar。应用、数据库和负载器同机。外部部署需配置 TLS；本轮仅验证回环 HTTP，未验证公网入口或 Docker / Nginx 部署。默认没有允许跨域的配置；管理接口要求当前启用 ADMIN。

Flyway 自动校验并应用迁移，clean 禁用。当前只有既有 V1；不得修改已执行迁移。健康检查为 `/actuator/health`，其他管理端点未暴露。记录运行包 SHA-256、Git 提交、组件版本及启动时间，以区分部署版本。

完整回归还会在测试库内创建随机 `b5_<标记>_` 前缀的空表命名空间，只替换 V1 表名前缀，验证首次迁移、12 表结构及重复迁移。专用测试账号不授予 DROP，因此这些空表及独立历史表留供复核；原 tf_* 业务表与 flyway_schema_history 不修改。此验证不是清空现有库或新建独立 MySQL 实例。

## 2. 只读对账

```powershell
pwsh -File scripts/reconcile.ps1 -Mode test -MysqlPath mysql.exe
pwsh -File scripts/reconcile.ps1 -Mode test -TierId 123 -MysqlPath mysql.exe
```

默认 Mode=dev；TierId=0 表示全量。脚本读取对应专用账号配置，在 REPEATABLE READ 只读一致快照中执行核对。先输出数据库、观察时间和范围，再输出 category、resource_id、detail；无差异时只有观察信息与列头。数据库执行失败返回非零；差异是报告结果，须阅读内容，不能仅凭进程退出码判断一致。

检查 STOCK_BALANCE、MISSING_STOCK、PURCHASE_SLOT、PAYMENT_REFUND、STOCK_LOG、ORDER_SNAPSHOT、REQUEST_TERMINAL。TierId 筛选订单及库存，该范围涉及用户的请求终态也会检查。既有白盒测试可留下故意不完整的历史数据，使用新实验票档范围核查，不能把历史测试差异当作真实业务故障，也不能忽略生产差异。

对账不更新数据、不补记录、不释放库存。发现生产差异后保留快照、关联 traceId 与订单号，判断是否为进行中的维护或真实缺陷；修复另行设计并审批，禁止直接把余额改成“看起来正确”。

## 3. 日志与恢复

每条 HTTP 完成日志包含 traceId、method、path、status、outcome、elapsedMs。outcome 为 SUCCESS、REJECTED、SYSTEM_ERROR；日志不记录请求体、查询参数或 Authorization。数据库及系统错误另记异常类型和 traceId，客户端不接收 SQL 或堆栈。

关单默认启动补扫、每轮完成后间隔 10 秒，100 条分页、10 秒预算、逐单事务，失败下轮重试。故障日志含 orderId 和 traceId。禁用账号仍可回收过期占用。失败订单持续存在时须排查数据及数据库错误，其他订单继续处理。

客户端收到 500/503、断连或响应丢失，保留原 Idempotency-Key 重试；不能换键猜测上一请求失败。数据库提交可能已完成，原键可恢复历史结果和当前订单状态。不得删除请求记录以强制重新执行。

## 4. 实验复现

先运行完整回归并构建 jar，再执行以下阶段；各阶段顺序运行，不与其他压测或构建争用资源：

```powershell
python scripts/batch5-experiments.py --phase recovery --java java.exe --mysql mysql.exe
python scripts/batch5-experiments.py --phase contention --java java.exe --mysql mysql.exe
python scripts/batch5-experiments.py --phase performance --java java.exe --mysql mysql.exe
python scripts/batch5-experiments.py --phase expiry --java java.exe --mysql mysql.exe
```

Python 3.12 与 requests 为实验工具依赖；Java 17 直接执行 scripts/TestKeys.java 生成临时密钥。`--output` 指定结果 JSON，默认 .tools/batch5-experiments.json；每阶段使用不同文件名以保留历史。性能同时生成逐请求样本 CSV。工具只强杀自己创建的 JVM 句柄；不停止 MySQL，不清空既有库。每次追加带唯一标记的独立数据，数据准备与注册登录不计入测量。

网络故障通过仅监听回环的测试代理控制实际 COMMIT 报文或 HTTP 响应；正常性能阶段直接连接数据库。实验前确认机器可持续运行；脚本在 Windows 运行期间请求保持系统唤醒，退出时恢复。暂停、睡眠或严重资源争用造成的异常须保留并重跑，不能当作稳定基线。

### 7.2 批次7应用接入

执行`./scripts/run.ps1 -WithRedis`启用缓存和同步限流。start-tunnel.ps1以隐藏独立进程建立SSH回环转发，所有端口已监听时复用，部分占用时拒绝替换；不能将仅有监听当作认证成功。common.ps1随后通过已授权SSH在内存读取Redis密码，并执行有超时的AUTH/PING预检，再传递环境变量；退出清除凭据，不将密码放命令参数、仓库或报告。无开关继续默认关闭Redis功能。远端地址变化时同步更新common.ps1的受控读取地址和隧道。

独立隧道不会随应用/测试退出自动关闭；本次创建的进程ID记录在忽略目录`.tools/tunnel.pid`，诊断在`.tools/tunnel.stderr.log`。结束使用时先核对该PID仍对应项目SSH进程再停止；复用用户已有隧道时不记录或终止其进程。服务器节省停机后该连接可能退出，下一次运行自动重新建立，不在脚本中购买或启动云实例。

完整回归使用`./scripts/test.ps1 -WithRedis -Clean`，专用ticketflow_test/tf_test与随机tf:test命名空间；Redis集成测试删除自己的键，不执行FLUSHDB。不传WithRedis的普通回归会跳过Redis两类测试，不能报作完整批次7验收。Flyway新增V2目录版本表，保留V1哈希；空表命名空间迁移验证同步覆盖两份迁移。

### 7.3 批次8RabbitMQ实验入口

独立执行`./scripts/mq-lab.ps1`；完整回归执行`./scripts/test.ps1 -WithRedis -WithRabbitMQ -Clean`。需云实例已运行，RabbitMQ4.3.6、SSH免交互认证、三端口隧道及本机ticketflow_test配置齐备；脚本只检查/连接，不启动云实例或购买资源。普通无WithRabbitMQ回归会跳过MQ类，不算完整批次8验收。

common.ps1捕获远端.env中的RabbitMQ密码，只保存在当前环境变量，管理overview认证预检成功后交给Maven，finally清除。管理请求固定HTTP/1.1，避免SSH连接下Java默认h2c升级失败。测试用管理员凭据创建随机vhost及专用无管理权限用户，AMQP使用该专用用户；不在命令参数、报告或仓库保存凭据。JUnit XML含运行环境属性，不能直接提交，交付仅抽取白名单测试结果。

工作、三条重试及死信队列均为持久quorum，资源前缀lab.*；临时vhost内at-least-once死信/reject-publish策略不改变开发vhost。预取1、并发去重实验仅两个消费者，队列长度限1000。默认退避400/800/1600ms；独立参数实验可运行`./scripts/mq-lab.ps1 -RetryBaseMillis 200 -TestCase boundedBackoffThenSuccessfulRetry`，范围100～2000ms，不能作为生产重试参数。

完整MQ实验最后会执行一次`docker compose restart rabbitmq`，短暂断开所有RabbitMQ连接；请在空闲学习环境执行。Redis不重启、不开放6379/5672/15672公网端口。AMQP等待恢复后只做queueDeclarePassive，证明恢复未依赖重新建队列。子进程强杀只针对本次启动并持有Process对象的实验JVM，不终止其他Java进程。

正常/断言失败退出尝试清理本次vhost和用户；结果写入忽略的backend/target/mq-lab-observations.json。整个父测试进程若被强杀或管理连接不可用，清理钩子不能保证执行，应按本次记录的精确vhost/用户核查清理，不按通配符删除。MySQL测试账号无DROP，保留随机b8_*三表；生产Flyway仍仅V1/V2，不给测试账号扩大权限。不要把实验DDL手动执行到ticketflow_dev。

隧道不是永久可靠连接，ServerAlive用于发现断连、不自动重连。本批曾在预检成功后发生Connection reset，Redis/MQ用例实际未通过；先保存失败证据并确认云端容器健康，再由start-tunnel.ps1恢复认证隧道，完整重跑。不能跳过受影响用例或把预检成功当作整轮依赖可用证明。


### 7.4 批次 9：异步运行配置

2026-10-07 晚服务器节省停机重启后，公网 IP 已变为 `120.27.140.184`。已用原可信 ED25519 主机密钥核验为同一实例；SSH 使用 HostKeyAlias=118.178.253.75 读取原信任记录，不放宽 StrictHostKeyChecking。脚本默认新地址，后续地址变化使用 TF_ECS_HOST 覆盖；监听端口不能证明隧道有效，仍有 Redis/Rabbit 认证预检。实例启动由用户控制，不采购/升级或自动启动云实例。

```powershell
./scripts/setup-async.ps1
./scripts/test.ps1 -WithAsync -Clean
./scripts/run.ps1 -WithAsync
```

setup-async 为已授权开发环境创建或更新无管理标签的 tf_app，权限仅 `/ticketflow-dev` 和 `^tf\.dev\.async\..*`，设置 quorum at-least-once DLX/reject-publish 策略。专用随机密码生成于服务器 `/opt/ticketflow/.env`（600），在 SSH/管理隧道中处理，只保存在内存/进程环境；不用 tf_admin 运行订单消费者。脚本不新增公网端口。

-WithAsync 自动连接 Redis 与应用 Rabbit 配置，默认不开关时不启动异步网络任务。普通 SYNC 保留原路径；运行模式更新仅在开售前允许。Flyway 增量 V3 加入场次 mode、五张异步表及已有数据 gate/balance 回填；V1/V2 保留。test 数据库账号既有 ALTER 权限足够，未扩大权限、未清空测试库或 DROP 旧表。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| TF_ASYNC_ENABLED | false | 启用 ASYNC 配置与后台任务 |
| TF_ASYNC_JOBS_ENABLED | true | 已启用异步时，开启启动补扫/发布/消费；测试可禁用 |
| TF_RABBITMQ_HOST / PORT | 127.0.0.1 / 15673 | AMQP 隧道 |

工作队列与死信队列均 durable quorum、长度 1000、溢出 reject-publish；单机没有 HA。发布 persistent+mandatory，confirm ACK 且无 return 才标记 SENT。消费者 4、prefetch 8、手动 ACK。连接/握手 3 秒、确认等待 2 秒、心跳 10 秒；关闭自动网络恢复，由下一任务周期重新连接，拓扑在每个新连接初始化一次。

发件箱分 REDIS/BROKER，各轮最多 100 条、总预算 5 秒、8 秒领取租约，失败 1/2/4/8/30 秒退避。消费者工作租约 8 秒、实际交易 5 秒，系统失败 1/2/4/8 秒重试、最多 5 次执行；阈值进入 DLQ 并记录定位日志，数据库记录仍由截止扫描跟踪。扫描间隔 2 秒、最多 100 条、预算 5 秒，启动补扫，不能延长原建单截止。

结果查询在 Redis 不可用时仍读 DB；新受理遇断连、缺键、部分回执或时钟偏差 >1 秒暂停相关 ASYNC 场次。当前只有开售前视图初始化，没有开售后自动重建；恢复操作留批次 10，不能手动把 DB available 全量写回 Redis 或仅把 phase 改成 READY。Lua 已预占但最终未可靠入库的孤立 token 当前不会按 TTL 自动释放，原键可在准入有效期内恢复，完整封口协议待实现。

-WithAsync 的完整回归也包括原 Redis/MQ 实验，MQ 实验会正常重启 Rabbit 一次。测试使用随机专用 vhost/无管理用户，结束清理；异步 DB 与 Redis 使用稳定 `tf:test:v1`，保留持久记录及对应 token 以便重跑核查，避免随机命名空间丢失既有投影。测试仅清理自身实例资源，不 FLUSHDB，不删除异步 DB 历史。

`ticketflow.async.admission{outcome=有限集合}` 与 `ticketflow.async.consume{outcome=ACK/DEAD_LETTER/STOP}` 是尝试计数，不能当作唯一建单量；真实建单量应查 DB。请求/事件定位 ID 只进日志，不作为指标标签。完整恢复、积压告警、100 在途恢复和云端容量对照仍留后续批次。


测试脚本在需要中间件时启用仅存续于本轮 Maven 的隧道监督任务。三个回环端口全部丢失后重建 SSH 隧道；部分端口占用时拒绝替换，不能覆盖用户其他进程。重连时间记录到忽略目录 `.tools/tunnel-reconnect.log`，不记录凭据。finally 停止监督任务，保留独立隧道供后续使用；不重试断言、不跳过用例，任一真实失败仍使 Maven 失败。此机制只恢复测试传输通道，不能代替业务未知提交/孤立预占/Redis 重建的恢复协议。

当前 `scripts/reconcile.sql` 是 V1/SYNC 对账入口，其原 CREATE 幂等记录检查不适用于异步独立请求表；本批不据此判断 ASYNC 数据损坏或修复库存。完整 ASYNC 对账与孤立预占检查在批次 10 增补。
