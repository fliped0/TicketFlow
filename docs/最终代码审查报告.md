## 审查覆盖与源码结论

本次实际追踪请求入口、Service 事务、Mapper SQL、数据库约束、Redis Lua、Rabbit 适配、恢复扫描及 Agent 权限路径，同时检查前端原键恢复与测试断言。不是仅根据 README 推断；也不是形式化证明或对每个文件逐行无遗漏的安全认证。

| 审查领域 | 核查实现 | 结论及边界 |
| --- | --- | --- |
| 同步下单/事务 | `OrderApplicationService.createLocked`、`TradeExecutor.executeInSession/inTransaction` | 交易返回经过 commit；BusinessRejection 仅回滚保存点，系统异常退出整笔事务。原键唯一约束、摘要及用户锁保护重放，1205/1213 有限重试；未知提交不能凭异常补库存。 |
| 库存/限购 | `InventoryMapper`、`OrderMapper.hasSlot/insertSlot`、V1/V3 CHECK/FK/唯一键 | `available>=1` 条件扣减，受影响行数与库存流水同事务；数据库校验守恒。同步/异步资格靠共享用户锁与模式规则协调，两张独立唯一索引不是联合唯一保证。未发现可复现超卖路径。 |
| 支付/取消/退款 | `OrderApplicationService`、`OrderPolicy`、`OrderMapper.transition`、`PaymentMapper` | 时间在锁后由数据库读取，UPDATE 还限制状态和截止；唯一支付/退款及流水保护重复操作。模拟器无外部资金副作用，不能直接照搬为真实支付分布式事务。 |
| 到期关闭 | `OrderExpiryJob`、`OrderMapper.expired` | 原 keyset SQL、有预算/防重入和启动补扫正确；跨轮游标重置存在 R1。修复保留原状态与锁序。 |
| 缓存/限流 | `CatalogCacheService`、`CatalogService`、`RedisGateway`、`PurchaseRateLimiter` | 目录变更与 revision 同事务提交，旧版本不会填入新键；动态库存和时间查 DB。Redis 异常有受限回源；SYNC 限流失败放行仍依赖 DB 锁，ASYNC 新准入失败关闭。固定窗口和单进程配额有边界，见 R4。 |

## 测试质量判断

关键测试不是只断言 HTTP 200：`OrderIntegrationIT` 检查订单数量、唯一资格和库存流水，逐写入阶段注入回滚；`OrderLifecycleIT` 控制数据库锁的双向竞争并核对截止与余额；`RedisCatalogIT` 核对实际回源次数、失效、回源合并和配额；`RabbitMqLabIT` 包含 mandatory return、NACK、confirm 丢失及 broker 重启；`AsyncPurchaseIT` 包含真实 Redis/RabbitMQ、子进程强杀、数据库 COMMIT 代理及持久事实对账。

Agent 测试覆盖工具参数/路径、伪造和跨用户确认、确认过期、快照变化、未知提交、重启和旧响应隔离。网页模拟 API 测试不替代真实 Java/MySQL 测试；历史真实浏览器证据独立存放。

覆盖缺口：原扫描测试在下一轮移除了故障，或只构造不超过一个批次的可恢复请求，因此漏掉 R1/R2；本批先用失败回归证明缺口再修复。功能测试通过不能证明所有调度组合，更不等价于高并发性能/生产 SLA。当前没有本次依赖漏洞数据库扫描或最新模型能力评估，不作相关结论。
