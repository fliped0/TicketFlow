# 前端取消、全额模拟退款与最小闭环验收（2026-10-12）

## 交付

订单详情新增取消未支付订单和申请全额模拟退款，均展示成交摘要并要求独立勾选确认。取消摘要区分原订单金额与未支付退款金额（¥0.00）；已到支付期限的待支付单可以提交取消，由服务端关闭。已支付单仅在开场前提供全额模拟退款，成功后展示唯一退款编号、金额、时间；不发生真实资金交易。开场后禁用退款按钮和已打开窗口的提交，后端仍决定实际资格。

新增操作复用发送前持久保存、所属用户/origin 隔离、Web Locks、本页忙状态和原键恢复。成功回执分别核对订单、金额、终态及支付/退款编号；已有 v1 下单/支付记录保持兼容。未知结果不能换键覆盖或直接删除，查到订单终态也不自动抹去未知记录。明确的 REFUND_CLOSED/REFUND_SIMULATED_FAILURE 结束本次尝试；新的退款需再次明确确认。待支付和已支付详情可见且没有确认窗口时，每 10 秒只读刷新。

本机同步流程已完成：注册登录 → 浏览/选票 → 独立确认下单 → 模拟支付 → 我的订单 → 取消或全额模拟退款。Java 源码、API/OpenAPI、Flyway 与 CORS 未改；Agent 网页入口、异步购票、公网部署和真实支付不在本批范围。

真实库存场景使用独立容量 2 的票档：下单可售从 2 到 1，取消回到 2；同键重放及新键重复取消仍为 2。再次购买/支付后为 1，退款回到 2；原键与新键重复退款返回相同支付/退款编号，库存仍为 2。取消、退款后原用户均能再次购买同场，证明资格释放；订单过滤和退款记录一致。

真实丢回执场景先用 route.fetch 获得上游已成功提交的 200，再向浏览器断连。取消与退款刷新后用原键恢复，返回同一订单/支付/退款编号，库存不会再次增加。退款特意等到开场后恢复已提交成功，仍返回原成功回执；没有把首次执行的期限限制错误套到恢复操作。该实验是提交后浏览器收不到回执，未执行 JVM 强杀或 COMMIT 代理故障。

自然支付期限场景验证晚支付 ORDER_EXPIRED，随后通过网页取消得到 CLOSED。自然退款开场场景验证已勾选的窗口自动禁用，关闭后页面退款按钮禁用，服务端晚退款返回 REFUND_CLOSED，订单仍为 PAID、没有退款记录、库存保持已售占用。他人对订单发起取消/退款均返回 404；保留原有账号隔离、限购、最后一张票争夺及下单/支付恢复回归。

## 数据与边界

仅使用 ticketflow_test/tf_test、随机账号/独立活动、随机端口 Java/预览实例及临时 RSA；关闭关单/异步任务，无模型调用。本人待支付订单取消，可退已支付订单模拟退款，自身目录全部下架，子进程与临时密钥清理通过。每个视口的退款到期用例故意保留一笔 PAID 历史订单（最终 160249、160263），符合 REFUND_CLOSED；不能绕过规则强行退款，摘要单列。前两轮各保留两笔同类历史边界订单。没有清库、删除历史或在开发库做测试交易；本机开发前后端继续运行。

localStorage 的刷新恢复已验证，不宣称断电/磁盘故障恢复。清除站点数据、换浏览器或在未知交易期间更换代理目标仍需核查原订单；支持 Web Locks 的新版 Chrome/Edge 才允许写入。真实模拟器当前固定成功，退款失败通过模拟 API 和单元测试验证，未声称真实后端失败注入已执行。未重跑/累加历史 Java 或 Agent 集合，不作为生产容量或真实支付验收。NO_COLOR/FORCE_COLOR 工具提示未屏蔽。
