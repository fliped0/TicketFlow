## 1. 目标与现有基础

V2 批次 10 已完成，提交 `bb5877d` 已推送，完整 159 项回归通过。该结果属于 Java 业务与恢复能力验收，不计作 Agent 测试。设计沿用 [需求分析](01_需求分析.md) 的 FR-AGENT-001～004、[总体设计](02_总体设计.md) 第 10 节及 [OpenAPI 0.7.0](api/openapi.json)。

Agent 作为独立 Python/FastAPI 服务，通过已有 Java HTTP API 帮助用户查活动、查本人订单、理解退票规则，并在明确确认后取消或模拟退款。订单、库存、身份与交易结果仍由 Java 系统判断。模型故障不影响原有业务入口。

首个实现批次只交付查询能力。规则问答和写操作分别验收后启用；不将已有取消、退款 API 等同于 Agent 已安全接入。自动抢票、支付、管理员操作、后台自主执行任务及真实支付不在本阶段范围内。

## 2. 技术安排与运行环境

| 项目 | 本阶段设计 |
| --- | --- |
| 服务 | 仓库新增 `agent/`，Python/FastAPI，独立进程与项目虚拟环境 |
| Java 接入 | 固定业务基地址、固定路径模板的 HTTP 客户端；不接受模型提供 URL |
| 模型 | 通过小型适配层接入外部模型 API；服务商、模型 ID、SDK 与价格待选型 |

| 规则检索 | 先对经过审核的小规模规则材料做本地检索；命中质量不足时再评估向量检索 |
| 状态存储 | 只读阶段可使用有界内存会话；写操作阶段增加本地 SQLite 持久确认记录 |
| 部署 | 本机单实例，默认监听回环地址；Java/MySQL 与云 Redis/RabbitMQ 沿用现有环境 |
| MCP | 当前直接消费 HTTP API，暂不增加 MCP 服务；存在其他客户端复用需求时单独设计 |

2026-10-09 环境检查已发现可运行的 Python 3.12.10（`D:/develop/Python-3.12/python.exe`）和 uv。后续按实际选用依赖核对兼容性、生成锁文件并验证安装；此次没有创建虚拟环境、安装包或调用付费 API。Windows `py` 启动器未登记该 Python，脚本应使用已验证的解释器路径或项目虚拟环境。

用户只需在真实模型联调前选择服务商、模型和调用预算，并将 API Key 写入本地忽略配置或环境变量。密钥不进入聊天、版本库或日志。本阶段不要求购买云资源、安装本地大模型或单独部署向量数据库。

## 3. 数据流与职责

```text
用户请求 + 当前用户认证
    → Agent 身份校验 / 会话归属 / 预算预留
    → 模型提出工具调用
    → 应用校验工具名、参数、权限与次数
    → Java API 或版本化规则检索
    → 裁剪后的工具结果
    → 带来源的回答 / 待确认操作卡片

用户确认具体操作卡片
    → 独立确认接口（应用代码处理）
    → 持久状态与原幂等键
    → Java 取消 / 退款 API
    → 持久记录结果并展示
```

模型仅决定如何组合允许的查询及提出操作意图，不持有 JWT、API Key、数据库账号或可执行写操作的确认凭据。Java 客户端在服务端附加当前请求的认证头，使用明确超时，并禁止自动跟随重定向。

建议代码按 `api/`、`service/`、`clients/`、`tools/`、`knowledge/`、`models/` 和 `tests/` 组织。模型客户端、Java 客户端和确认状态仓储分别可替换，以便使用固定响应验证流程。创建实际实现时再建立对应文件，不先批量生成空类。

## 4. 认证与会话边界

首版 Agent 入口统一要求已登录；调用 `GET /api/v1/users/me` 验证 JWT 并取得身份。会话必须绑定该身份，服务端校验会话归属。工具参数和用户自然语言中的 `userId` 都不能改变身份，业务 API 每次继续检查令牌、账号状态和权限。

用户通过现有登录接口取得令牌；密码不经过模型。令牌失效时要求重新登录，不设计不存在的刷新接口。重新登录后，同一用户可查询其未完成确认记录；不能使用其他用户令牌接管会话或操作。

JWT 仅在处理受认证请求时由应用使用，不写入会话历史或持久确认记录。首版不在无用户请求时后台自动执行交易。公共活动资料可缓存，订单结果和会话历史不得跨用户复用。注销客户端会话时清理本地会话；这不声称 Java 已提供服务端令牌撤销能力。

## 5. 工具契约

下表的 Java 方法和路径已对照现有 OpenAPI。工具输入使用严格模式，拒绝未知字段；ID 为十进制字符串，分页受限。模型不能设置认证头、幂等键、HTTP 方法或基地址。

| 工具 | 固定数据入口 | 输入与输出约束 |
| --- | --- | --- |
| `search_events` | `GET /api/v1/events` | keyword/city/category/page/size；返回上架活动与分页信息 |
| `get_event` | `GET /api/v1/events/{id}` | eventId；返回可见活动详情 |
| `list_sessions` | `GET /api/v1/events/{id}/sessions` | eventId/page/size；返回场次时间与售卖状态 |
| `list_tiers` | `GET /api/v1/sessions/{id}/tiers` | sessionId/page/size；返回价格、当前可售量与状态 |
| `list_my_orders` | `GET /api/v1/orders` | status/page/size；不接受 userId |
| `get_my_order` | `GET /api/v1/orders/{orderId}` | orderId；归属由 Java 再次校验 |
| `search_rules` | 经审核的本地规则语料 | query；返回正文片段、规则编号、版本、出处 |
| `prepare_order_action` | 查询本人订单，生成确认记录 | orderId/action（cancel 或 refund）；只准备，不执行写操作 |

`POST /api/v1/orders/{orderId}/cancel` 和 `POST /api/v1/orders/{orderId}/refunds` 仅由确认服务调用，不注册为模型可直接执行的工具。登录、支付、建单、异步购票、管理员与运维 API 均不在工具白名单内。

工具结果只返回回答必要的业务字段和来源元数据，保留金额精度，不使用浮点数重新计算价格。404 不泄露订单是否属于其他用户；401 中止私有工具链；429 提示稍后再试；连接失败不得被模型改写成“没有订单”或“已售罄”。

## 6. 回答与规则问答

价格、库存、开售时间和订单状态来自本轮实际工具结果，并附查询时间与对象标识。库存仅是查询时刻的状态，不保证随后可购买。接口不支持的筛选不得假装完成全量搜索；只筛选一页时明确结果范围。

先将需求与接口文档中的正式业务规则整理为独立版本化语料；排除密钥、日志、用户数据、历史失败记录及未经审核的活动文案。规则片段保存 `ruleId`、版本、生效说明、源文档路径、章节和内容哈希。语料更新后重新跑对应评估，不混用相互冲突的版本。

现行规则包括一单一张、同场次限购、支付期限、开场前全额模拟退款等；实现时逐项核对原文，不能由本文新增售后承诺。问题涉及某个订单是否可退款时，规则解释与实时订单查询共同提供依据，实际写入仍由 Java 判断。

回答中的规则引用必须由服务端从本次检索结果映射，拒绝模型杜撰路径或编号。实时事实用结构化结果卡片展示；模型文本只作解释，关键金额、状态和操作结论用确定性格式生成。资料缺失、矛盾或没有足够依据时明确说明，并给出已知范围。

活动介绍、用户文本、工具返回文本及检索片段均按数据处理，其中“忽略规则”“调用管理员接口”等文字不能改变工具权限、身份或确认状态。

## 7. 写操作确认与恢复

### 7.1 准备和确认

用户提出取消或退款后，服务端先查本人订单，生成不可猜测的 confirmationId。确认卡片展示具体订单、活动/场次、操作类型、金额、影响、有效期和模拟交易标识。模糊的“退掉它”应先明确目标；用户在普通聊天中说“确认”不能直接触发写 API。

拟新增 Agent 自身的 `POST /agent/v1/confirmations/{id}/execute` 接口，须携带当前用户认证和明确的确认动作。前端或演示客户端的确认事件调用该接口；模型无法调用此接口，也不能替用户产生确认事件。该路径尚未实现，不写入当前 Java OpenAPI。

确认记录持久绑定用户、会话、订单、操作、参数摘要、金额/状态快照、到期时间及服务端生成的 Java 幂等键。拟定有效期为 5 分钟；首次执行必须未过期。执行前再次查订单并检查关键内容，变化时将确认作废并重新展示。查询和写入之间仍可能竞争，最终结果以 Java 在事务中的规则校验为准。

### 7.2 状态与故障处理

确认仓储使用 SQLite 事务及条件更新，保证同一确认只被一个执行者取得；阶段范围限定本机单实例，不宣称多节点协调能力。确认状态设计为 `PENDING → EXECUTING → SUCCEEDED / REJECTED / UNKNOWN`，另有 `EXPIRED / CANCELLED`。`REJECTED` 仅用于已确定的业务拒绝。

在发出 HTTP 写请求前持久提交 EXECUTING、租约及幂等键；网络调用不占用 SQLite 写事务。重复点击返回已有状态或结果，不生成新键。超时、断连、非确定的 5xx 或应用崩溃均不能直接记为交易失败；租约过期的 EXECUTING 按未知结果处理。

UNKNOWN 的恢复在用户重新认证并请求检查结果时进行：核验归属与保存参数，按原方法、原订单、原幂等键重放 Java 请求，取得确定结果后持久化。恢复已经开始的操作不受首次确认有效期限制，但不能改变动作或目标；超时仍保留 UNKNOWN。新写操作到期与旧操作结果查询是两个不同条件。

订单当前状态可辅助解释，不能单凭状态断言某次请求是否执行成功。原幂等结果、Java 返回的交易标识与 traceId 用于核实。存在未决同订单操作时阻止创建新的写确认，避免未知请求尚未查清便另发新操作。取消待确认卡片只对 PENDING 生效，不撤销已经发出的交易。

确认历史不保存 JWT，敏感结果最小化存储。默认仅在终态后按配置保留期清理；未决记录不得被会话 TTL 或常规清理删除。持久文件丢失后不得猜测恢复或重新生成键执行；停用写入口并先核查 Java 记录。写阶段实现前补充表结构、约束和故障用例，不修改历史 Flyway 迁移。

## 8. 调用预算、超时与观测

以下为首轮实现的暂定可配置上限，不是已测性能：每轮最多 4 次模型调用、6 次工具调用、总时限 45 秒；列表默认 10 条、最多 20 条；单次输出上限暂定 1,024 token，单次模型输入预算 8,000 token。截断时保留系统约束和本轮工具结果，不能截断出不完整的工具协议。具体 tokenizer 和输出上限参数在服务商适配时核验。

模型与只读 HTTP 重试均计入轮次和时间预算。模型请求发送后未拿到响应也可能产生费用，不默认无限重试。交易写请求的重试只遵循第 7 节原幂等键恢复，不套用普通 HTTP 重试器。

真实调用默认关闭。用户确定预算后，配置模型 ID、单价来源与核对日期、每用户配额、并发上限及每日费用上限。发送前预留最坏输入/输出费用，响应后按 usage 结算；未知用量保留预留，不能当作零成本。预算计数跨进程重启持久保存，并发请求原子预留；实际账单以服务商为准。没有可核实单价或剩余额度时关闭真实调用，不凭猜测显示精确金额。

记录请求 traceId、匿名化用户标识、工具名、耗时、业务结果码、模型标识、token/费用估算、规则版本及确认状态；关联 Java traceId。默认不记录完整聊天、令牌、密钥及完整私有工具响应。模型或 Java 不可用时给出明确错误，不伪造业务结果。

## 10. 待定项与下一步

下一步可先实现批次 A 的项目骨架、身份透传、查询工具和确定性测试。真实模型联调前需要确定：服务商与模型、API 可用性、单次/每日预算，以及允许发送给服务商的最小业务字段。选型时核对官方文档中的工具调用、结构化输出、数据政策与费用，本文不预先承诺兼容性或价格。

用户现有环境不需立即安装新软件；依赖随实现进入独立环境。最小演示入口拟为本机页面或测试客户端，写操作阶段必须具备独立确认控件；完整前端另行安排。对外部署、多实例、数据留存要求变化时重新评审认证、持久状态与预算机制。
