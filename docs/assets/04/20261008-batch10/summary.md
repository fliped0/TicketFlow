## 实现与实际验证

| 范围 | 验证 |
| --- | --- |
| 孤立封口 | 原键无持久行先提交 ADMISSION_EXPIRED/REJECTED 与确定性 RELEASE；重复扫不多补；迟到 HTTP 与封口双向锁竞争；已受理未知响应不释放 |
| 跨场次原键 | 只封口/释放输家候选，不改变胜者在途资格或订单 |
| epoch 重建 | 全量/部分 Redis token 丢失、在途与 PAID/PENDING 订单重建、取消/退款跨重建正确回补；原截止保持不变 |
| 维护隔离 | 新维护版本使旧协调者无法 READY；快照对账差异不开放；Redis 写成功但响应丢失后等待租约失效并使用新 epoch |
| 子进程强杀 | 受理提交前/后、真实 Rabbit 消费建单提交前/后，以及 PAUSED/冻结/快照提交/Redis 恢复/DB READY/Redis READY 六个重建边界，共 10 个窗口 |
| 真实数据库断连 | 测试专用 MySQL 协议代理阻断目标 COMMIT 发出前，或收到服务器 COMMIT OK 后丢弃确认；原键按实际持久事实恢复，无盲目补偿 |
| 连续投影 | 从 DB 补齐前驱，包含已 SENT 事件；旧 epoch 不重复释放，新 epoch 旧消息由持久替代事件接续 |
| 死信重放 | 实际第五次消费失败进入 DLQ/持久告警；重放回执与替代 outbox 同事务；ACK 丢失重复操作仅一份替代工作；错误信封拒绝 |
| 自动扫描 | 定时恢复检测旧视图缺失，完成重建后重新开放；工作/截止扫描独立于 Rabbit 可用性 |
| 运维 | 本地 alerts/audit/rebuild/replay；只读 SQL 包含异步余额/资格/订单归属/序号；在线采样重复检查与水位记录 |

强杀由测试父进程对明确创建的子 JVM 执行，且等待退出。消费故障窗口的截止从子进程就绪后设置测试夹具；部分重建用例通过测试库时间夹具使维护租约失效。这些定位窗口的测试不作为真实租约等待或启动 SLA 测量。100 请求收敛用例不延长生产默认建单截止。

## 开发失败与修复

首轮异步验证 **41 项 / 2 失败**：新测试误用支付路径；发件箱旧事件/共享预算影响后续投递。修正接口路径、独立 REDIS/BROKER 预算、失败退避后继续其他事件。

第二轮 **51 项 / 4 失败**：测试子进程直接 spy Spring Repository 代理导致故障钩子未装配，冷 Redis 初始化造成 CLOCK_SKEW，既有单次 dispatch 断言在 100 请求夹具后过早。改为 spy 真实 mapper 目标、在测试子进程先建立 Redis 连接、按有限调度周期验证。该轮 6 个重建强杀窗口已实际通过，但整轮仍判失败。

两轮 100 请求分别 40.549/42.378 秒全部截止拒绝，未称为建单吞吐收益。随后定位旧 epoch BROKER 事件仍占据网络投递，改为在迁移/替代工作已持久化后跳过旧事件。定向 10 项全部通过，恢复 40.726 秒 / 60 成功；最新完整清理回归 159 项全部通过，最终恢复值以 41.452 秒为准。

早期构造器编译适配失败和沙箱内 ByteBuddy 附加受限的单元运行未计通过；停住的本次专用测试进程已按父子关系核验并清理，最后在获准环境完成全部 14 项单元回归。失败轮次/用例与修复说明见 [首轮](first-async-results.json)、[第二轮](second-async-results.json)、[定向复测](focused-results.json)。报告抽取脚本曾把字典对象误用于 Measure-Object，归档前改用具名对象并与全部 XML 套件计数核对，不改变产品测试结果。
