# 异步抢票前端闭环

2026-10-14。本批复用已实现的 Redis/Lua、数据库受理与 RabbitMQ 消费协议，将异步场次接入网页。

## 范围和验收

1. 场次列表增加 `purchaseMode: SYNC | ASYNC`，普通场次下单、异步场次抢票。无法识别模式时暂停提交，要求刷新。
2. 独立核对并确认票档与金额后，先保存原请求键和参数，再提交抢票。202 只表示受理，不显示虚构排队名次。
3. 已知请求编号仅 GET 查询；尚未取得回执时，由用户显式恢复原键 POST，不能自动重复提交。
4. 展示排队、生成订单、等待服务恢复、成功与拒绝。客户端超过处理截止只提示继续核查，不自行判定失败。
5. 页面可见且在线时轮询，成功受理至少间隔 2 秒；查询失败递增退避至 30 秒并遵守 Retry-After。刷新及重新登录恢复，其他账号不展示原记录。
6. 同步交易、助手确认与抢票共享按用户的跨标签页锁，未决请求阻止新写入；未知请求不可删除或换键覆盖。
7. 成功生成订单后，在原活动页自动进入订单详情，沿用模拟支付、取消与退款。其他页面提供订单链接。

真实验收覆盖：受理后刷新并支付、丢失受理回执原键恢复、跨账号 404、两名用户同时抢一张票最终只生成一单。使用专用测试库及独立 RabbitMQ 测试账号/vhost；测试目录下架，生成的有效订单按业务 API 取消或模拟退款，关闭自建测试进程。

## 兼容与边界

公开场次与管理员场次增加字段，OpenAPI 升级到 0.8.0；场次缓存参数增加结构版本，避免复用旧字段缓存。历史 Flyway 迁移保持原样。旧的同步与助手恢复记录无需迁移。

网页保存当前账号的一份抢票恢复记录；清除浏览器存储或跨浏览器不能自动找回原键，须先核查订单。客户端无法取消尚在处理的抢票请求，成功生成订单后可走现有取消流程。真实资金、管理员页面、公网部署及容量承诺另行安排。
