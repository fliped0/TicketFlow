# Agent 千问路由协议修复（2026-10-11）

本批修复强制函数路由与结束标记兼容性，冻结真实模型集 **60/60**、完整确定性测试 **266/266**、真实 Java/Agent/MySQL 联调 **23/23 组**通过。没有修改冻结题目、预期或计分标准。本次为已见固定集的回归验证，不代表未见问题的广泛准确率，也不能据一次通过保证模型始终稳定。

## 问题与修复

旧请求同时允许原生工具调用与自由 JSON；历史四轮得分为 59、58、58、57/60，最后仍存在规则咨询、退款准备和跨用户路由失败。证据保留在[原批次 C](../20261010-agent-c/summary.md)。

当前指定千问接口与 qwen3.8-flash 使用一个强制命名函数 `route_request`，移除竞争的 `response_format`。嵌套工具参数沿用真实工具 schema，服务器校验全部路由后才执行查询。强制命名函数采用[千问官方 function calling 接口](https://platform.qianwenai.com/docs/developer-guides/tool-calling/function-calling)。

开发探测发现该接口将完整原生工具调用标记为 `finish_reason:stop`，旧解析因此误报格式错误。适配器仅在函数名、数量、ID、严格 JSON、工具白名单、参数和结束状态全部有效时接受这种返回；截断、纯文本、未知工具、重复键、伪造身份字段和混合结束状态仍拒绝。没有模型自动重试，每轮仍最多一次实际 HTTP 请求，Java 结果与认证信息不发送给模型。
