第一批提供 3 个用户 API 和 1 个健康接口；第二批新增 4 个公开目录与 11 个管理员目录接口；第三批新增 3 个下单及本人订单查询接口；第四批新增取消、支付、退款 3 个接口，共 25 个已实现 HTTP 操作。系统关单为内部入口；订单与统计管理接口待后续批次。存在迁移表不代表业务已完成。

第三批以 JdbcTemplate 实现 TradeExecutor、OrderApplicationService、InventoryService、DatabaseClock 及相应 Mapper，沿用统一分层与单事务 READ COMMITTED。先锁当前用户并重新检查 enabled，随后处理请求键；业务拒绝回滚保存点并提交 REJECTED，系统与数据库异常整笔回滚。下单按父目录到库存有序锁定，在锁后用新 SQL 取 UTC 时间，订单、资格、库存和流水共同提交。本人查询保留成交快照，他人订单与不存在统一 404。

批次 3 交付时完整回归为 12 项单元测试和 33 项真实 MySQL / HTTP 集成测试，共 45 项，0 失败、0 错误、0 跳过。第三批新增 3 项规则单测和 15 项交易集成测试：保存点撤销、五处写入故障全回滚、SQL 唯一冲突、有限锁重试与真实锁超时、20 次同键并发重放、同键异参、跨票档限购、最后一张票竞争、下架双方先持锁、锁后跨开售/停售时间、锁内账号禁用复查，以及本人查询与输入类型校验。

批次 3 接口文档为 0.3.0；测试范围、命令、实际结果与源码哈希见[批次 3 测试报告](assets/04/20261001-order/summary.md)。校验 OpenAPI 时修复了旧目录请求体的空 schema 引用，并去掉 GET 请求体。既有迁移 V1 未改动。

批次 4 已实现主动取消、模拟支付、超时关单及模拟退款。取消未到期 PENDING 转 CANCELLED，到期后统一 CLOSED；支付将占用转已售且保留资格；开场前全额退款归还已售并释放资格。历史成功重复操作不再次迁移；模拟失败原键重放、新键可重试。详情展示支付与退款记录，交易重放保留 paymentId/refundId 及历史状态。

OrderExpiryJob 默认启动补扫，每轮固定数据库截止点、100 条游标分页、10 秒预算，完成后间隔 10 秒扫描；逐单内部事务不要求幂等键，也不因 enabled=false 跳过。失败继续处理后续候选，下轮重试；同实例互斥。支付、取消、退款与系统关单遵循相同的用户→订单→资格→库存锁协议，关键时间在锁齐备后重新读取。

批次 4 测试范围与交付结果见[生命周期测试报告](assets/04/20261003-lifecycle/summary.md)，接口文档升级为 0.4.0，既有 Flyway V1 保持原样。已验证正常应用上下文关闭后重启补扫与后续定时扫描；强杀 JVM、提交未知恢复、1000 用户/100 工作线程/100 张票三轮实验和性能 SLA 未执行，未宣称完整 V1 验收。
