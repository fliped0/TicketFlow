## 2. 实际实现与限制

当前网关采用 **一次结构化解析**：可返回原生工具调用或严格 JSON，统一通过工具白名单、参数 schema、批量查询前整批校验。服务器执行独立只读查询并直接组装 Java 数据卡片；普通模型文本不展示为业务事实。缺少条件使用固定字段枚举，未知工具/字段、虚构结果索引、截断与畸形输出明确拒绝。

模型不接收 Java 结果、身份、JWT 或 Java traceId，只见用户问题、系统约束和允许的工具定义。默认只开放四项公开目录工具；六项认证直接查询仍可使用。私有工具开关的开启/关闭用模拟网关验证，真实订单自然语言质量尚未验收。用户自己的输入仍会发送到模型，应只填写查询必要条件。复杂链式规划、多轮记忆、规则检索/引用、确认取消/退款、未知交易恢复与生产部署均未交付。

每轮最多 6 次工具查询、总时限 45 秒；Java HTTP 5 秒，模型 HTTP 30 秒；正常网关最多一次实际模型 HTTP 调用，不自动重试。完整请求最多 8,000 UTF-8 字节，输出 `max_tokens=1024`。字节不是精确 tokenizer 数量。

本地默认每 UTC 日 20 次模型请求、每用户 10 次、10 RPM、200,000 记账单位。SQLite 发送前原子预留、重启保持；网关报告 usage 后结算，超时/缺 usage 保留 9,024 单位。该单位是保守本地计量，不是精确 token 或货币费用；学校实际额度以控制台为准。账本不保存密钥、提示词或业务响应，损坏时不自动清账。

最终测试记录：共 **17 次模型请求，32,267 记账单位，1 次未知用量**，包含前述开发失败和单次公开探测，没有清零。当天本地总请求额度余 3 次；UTC 日界在北京时间次日 08:00，学校月度额度是独立规则。详见 [用量快照](usage.json)。

## 3. 失败与修复

| 记录 | 实际失败 | 处理 |
| --- | --- | --- |
| [首次模型联调](first-failed.json) | 结果按普通 user 消息回传，重复公开查询直到 4 次上限 | 改为标准 assistant/tool 回传并增加重复查询保护 |
| [等待超时](timeout.json) | 20 秒未取得响应，usage 未知 | 单次等待改为 30 秒，9,024 单位预留保留，不自动重试 |
| [追问失败](clarification-failed.json) | 公开查询链已通过，但追问输出不符严格工具协议 | 尝试 required 工具选择，保持拒绝普通业务文本 |
| [required 失败](required-failed.json) | 仍重复详情/场次查询，服务端阻止再次查询 | 尝试查询后只选择 finish |
| [finish 失败](finish-failed.json) | 强制结束仍返回普通文本 `stop`，无法当成工具输出 | 收敛为一次解析，允许严格 JSON 路由，查询结果本地生成卡片 |

最后一次解析模式完整通过 12 组，不再请求模型总结查询结果。失败时已经通过的直接查询只记为部分通过，未把整次运行记为成功；早期报告缺少 `passed` 的失败文件在归档时补充 `false` 和运行日志中的安全错误码，未篡改检查或时间。原始日志保留于本机忽略目录，不归档聊天、令牌、密码或学校密钥。

配置阶段第一次本机令牌在模型列表接口返回 401，用户重新配置后返回 200，所选模型可用；随后探测实际生成 `search_events`，使用 1,340 tokens，见 [探测记录](probe.json)。模型探测只证明一次解析，不算完整 Java 联调。
