## 1. 目标与范围

在现有仓库新增独立的 `frontend/` 工程，采用 **Vue 3 + TypeScript + Vite + Vue Router + Pinia + Element Plus**，实现本机可运行的中文票务商城。

首批完成：**注册登录 → 浏览活动 → 选择场次和票档 → 确认下单 → 模拟支付 → 查看订单 → 取消或模拟退款。**

仅支持同步购票；Agent 面板、管理端、异步抢票和公网部署留后续。界面采用浅色商城风格，兼顾桌面与手机窄屏布局。

## 2. 工程与页面

- 前后端独立启动、独立构建，共用现有 Git 仓库。Vite 固定使用本机 `5173` 端口，将 `/api` 代理到 Java `8080`，不放宽后端 CORS。
- 前端按页面、公共组件、API 客户端、类型及状态管理组织。Element Plus 提供表单、弹窗、分页和提示；活动卡片、购票流程与订单布局自行设计。
- 新增前端启动、测试说明和锁文件；依赖缓存、构建产物、浏览器测试报告不提交。

| 页面 | 功能 |
| --- | --- |
| 活动首页 `/` | 关键词、城市和分类筛选，活动卡片、分页、空状态及失败重试 |
| 活动详情 `/events/:id` | 活动介绍、场次与票档选择、实时价格及库存、下单摘要 |
| 登录／注册 | 输入校验、错误提示、注册后登录，成功返回原页面 |
| 我的订单 `/orders` | 状态筛选、分页、刷新、进入订单详情 |
| 订单详情 `/orders/:id` | 成交快照、金额、状态、支付截止时间、模拟交易记录和可用操作 |

没有活动海报字段，因此使用本地装饰图形及分类配色，不依赖外部图片服务、不修改目录数据模型。

## 3. API 与交易行为

**复用现有业务 API，不增加后端接口、不修改数据库。**

- 公共目录允许未登录浏览；下单和订单页面要求登录。令牌保存在当前标签页的 `sessionStorage`，刷新后调用 `/users/me` 验证身份；退出清理令牌和页面私有状态。认证过期时提示重新登录。
- API 客户端统一处理认证、超时和业务错误；ID 始终使用字符串，金额按整数分处理，时间明确按北京时间展示。活动文案以文本渲染。
- 下单固定一单一张。确认摘要显示活动、场次、票档、价格和数量；支付、取消、退款均需独立确认。支付与退款明确标注“模拟，不发生真实资金交易”。
- 提交期间禁用重复点击。交易前生成并持久保存幂等键、请求及所属用户；网络超时、断连或结果不明确时保留原请求，提供“查询／重试原操作”，不自动换键重新交易。
- 未决交易记录放在本机 `localStorage`，不保存密码或令牌；重新登录同一账号才能恢复，其他账号不展示、不执行。恢复完成后刷新服务端订单状态。
- 服务端明确拒绝时显示原因；只有明确结束的操作才允许用户发起新尝试。页面倒计时只作提示，实际支付、取消与退款资格以服务端结果为准。
- 当前公开目录没有购票模式字段。同步接口返回 `ASYNC_REQUIRED` 时提示“此场次暂不支持网页购票”，不自动切换到异步接口。

## 4. 本机演示与数据准备

新增 `scripts/setup-frontend-demo.ps1`，通过现有管理员 API 准备开发演示数据。

- 限定本机开发服务，使用已有管理员账号，密码安全输入；不自动提权、不清空数据库、不执行直接 SQL。
- 默认创建三类带“演示”标记的活动，每个活动一个场次、两个票档；票价为 99／199 元，每档 20 张，开场为创建后七天，停售为开场前一小时，完成创建后尽快开售。
- 将资源 ID 和准备进度保存到已忽略的 `.tools/frontend-demo/`，不保存凭据。再次运行优先复用仍在售且有库存的数据；过期或售罄时创建新批次，保留历史。
- 创建请求结果未知时，按本批唯一标记查询核对，不能盲目重复创建；无法唯一确认则停止并报告。
- 普通用户从网页注册。不预置共享用户密码。没有管理员时，在运行说明中给出现有管理员初始化步骤。
- 提供前后端分别启动的命令，以及首次演示的完整操作说明；前端构建结果用于本机预览，本批不发布网站。

## 5. 验证与验收

采用 **Vitest + Vue Test Utils** 验证关键前端逻辑，采用 **Playwright** 验证浏览器流程；真实业务联调仅使用专用测试库。

重点覆盖：

- 注册、登录、筛选活动、选择票档、下单、模拟支付和订单展示。
- 待支付订单取消、已支付订单模拟退款、订单状态刷新。
- 未登录跳转、令牌过期、他人订单拒绝、空列表和接口不可用。
- 售罄、未开售、已停售、同场限购、支付到期和异步场次提示。
- 重复点击、交易响应丢失、刷新后原键恢复、切换账号后的数据隔离。
- 桌面与手机窄屏布局、键盘操作、弹窗焦点及长文本展示。

验收要求：

1. 类型检查、生产构建及新增测试通过。
2. 在真实 Java／MySQL 环境通过浏览器完成购票、取消和模拟退款；响应丢失重试不产生重复订单或重复交易。
3. 测试使用随机账号与独立活动，不清空已有数据；记录执行结果、清理情况与验证限制。
4. 更新运行文档、开发进度和测试报告，经差异及敏感信息检查后按仓库流程提交并推送。

2026-10-12 已建立独立前端工程、安装依赖及 Chromium，通过类型检查、生产构建、1 项组件工具链烟测和 2 项浏览器工具链烟测。当前只有启动页与未知路由页，登录、目录、订单、交易恢复及演示数据脚本尚未实现；上述业务验收未执行。历史后端与 Agent 测试结果不作为前端验收结果。见 [环境验证记录](assets/04/20261012-frontend-env/summary.md)。
