# 审核规则资料

`rules.v1.json` v1.0.0，2026-10-10 对照正式需求、已实现 API 与 Java 交易判断审核，共 11 条规则，仅适用于 TicketFlow 模拟项目。该文件是明确选取的规则集，不扫描仓库、不抓取网络资料，也不包含用户数据、日志或活动文案。

原有规则使用 BR-001～BR-007；TF-RULE-SALE、DELIST、CANCEL、SIMULATION 是已有正式段落的检索编号，不是新增业务政策。每条包含审核后的回答文本、文本哈希、检索词组、版本、源文档段落/表格原文及其哈希。出处固定为 `docs/01_需求分析.md` 与 `docs/api/README.md`，还保存整份源文档的归一化 UTF-8 哈希。换行统一为 LF，不因 Windows CRLF 改变判定。

运行时验证规则版本、重复编号、审核文本哈希、源文档哈希、实际章节、段落原文与章节锚点。请求期间继续核对版本和来源快照，变更后停止规则回答并返回 `RULES_UNAVAILABLE`；六项 Java 查询仍能运行。文件缺失或损坏不自动用模型补写规则。

检索使用显式词组与匹配排序，默认最多 3 条、上限 5 条。未知政策、操作请求、实时数据和具体订单分别生成明确状态。聊天检索始终使用用户本轮原问题，模型不能通过删掉“到账时间”或订单编号来将资料不足改成确定承诺。Java 数据和规则结果都不回传模型，回答与引用由本地生成。

| 状态 | 行为 |
| --- | --- |
| MATCHED | 提供通用规则及出处 |
| INSUFFICIENT | 无足够依据，不承诺外部政策或到账时间 |
| NEEDS_ORDER_QUERY | 可解释通用规则，不能判断该订单是否可操作 |
| NEEDS_LIVE_DATA | 需查实际活动/场次，不从规则推断价格或库存 |
| ACTION_REQUIRED | 本阶段无法执行交易或修改规则 |

更新规则时，先核对正式需求/API 与对应 Java 判断；明确冲突并解决后增加语料版本、重新审阅回答与检索词组、更新原文/章节/哈希，重启 Agent 后重新评估。不能只修改回答或绕过来源校验。即使文档只是无关段落变化，也须重新确认来源哈希；这是本批保守的审核边界。

固定本地评估集位于 `agent/tests/rule-evaluation.v1.json`，在首轮评估前冻结 40 问和预期状态/规则编号。新增问题另增版本，失败时修实现，不改既定预期迁就结果。另有来源漂移、冲突/伪造引用、认证与模型改写问题测试。该本地集合衡量检索和确定性回答，不代表模型的自然语言准确率；真实模型联调独立报告。
