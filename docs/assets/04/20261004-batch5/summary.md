# 批次 5：管理报表、对账与本机 V1 实测

执行环境为用户确认的 Windows 本机、Java 17、Maven 3.9.12、MySQL 8.0.45；业务代码沿用 JdbcTemplate 与统一分层。交付包含管理员订单查询、区间统计、只读对账脚本及可重复故障/性能实验工具。原 Flyway V1 未修改，真实支付、Redis、MQ、Agent 与生产部署留后续阶段。

## 1. 完整回归与接口

最终 `clean verify` 于 2026-10-03 23:47:22 +08:00 结束，13 项单元测试、60 项真实 MySQL/HTTP 集成测试，共 **73 项通过，0 失败、0 错误、0 跳过**。新增 AdminReportingIT 12 项，覆盖管理权限、五状态明细、筛选分页、各自时间口径、负净额、并发一致快照、只读对账与植入差异、下架后历史订单、安全配置、售罄原键重放、SQL 约束及独立空表命名空间迁移。

证据：[构建摘要](verification.txt)、[测试结果](test-results.json)、[测试套件](test-results.txt)。OpenAPI 0.5.0 包含 26 个业务操作及 1 个健康操作；本轮所有操作均有实际成功请求，管理员票档列表以最终包独立补测。[入口覆盖](http-operation-coverage.json)、[静态契约检查](openapi-validation.txt)、[补测](http-supplement.json)。静态检查包含本地引用、唯一 operationId、路径参数及 GET 无请求体，不代替完整契约一致性验证；参数与权限边界由集成测试验证。

73 是测试方法数，46 是计划用例组数，两者分别记录。[用例追踪与执行边界](case-matrix.md)保留首批空库迁移的历史证据。本轮迁移在同一专用测试库的独立空表命名空间中执行原 V1 的前缀替换副本，首次 1 次迁移、再次 0 次；账号没有 DROP 权限，保留 12 张前缀业务表与独立迁移历史，不清空数据库、不扩大权限。

## 2. 事务故障与超时恢复

CREATE、PAY、REFUND、CANCEL 各执行提交前强杀、数据库确认提交后强杀、提交前数据库断连、数据库已提交但 COMMIT 确认丢失，共 **16 种故障**、8 次实际 JVM 强杀。代理处理真实 MySQL 协议，提交前验证无副作用，提交后同键恢复原结果；不凭 HTTP 失败推断未提交。另有 CREATE/PAY/REFUND **3 种真实 HTTP 响应丢失**，上游已返回成功后代理关闭连接，再用原键恢复；库存、资格、订单与支付退款各生效一次。

100 笔过期单从停止后重启至回收完成为 **12.788 秒**（启动就绪 12.735 秒 + 最后核对 0.053 秒）。包含禁用账号、持续失败单不阻塞其他候选、修复故障后后续扫描重试及重复扫描不重复释放。正常运行到期至关闭为 7.2523 秒；最终包复测为 **7.2372 秒**，满足 60 秒目标。[恢复矩阵](recovery-final.json)、[最终包部署及到期冒烟](final-package-smoke.json)、[关联 trace](trace-evidence.txt)。

故障矩阵与三轮争票使用缺失路由 404 修复之前的包；其唯一变化的应用类是 ApiExceptionHandler，交易、认证、时间与扫描类与最终包逐字节相同。最终性能、部署冒烟及接口补测使用完整回归的最终 jar，SHA-256 为 `49dd3688fd072b2f8de4578d8918c65668fb2f544525c1f8172e6d3531ba0294`。详见[包版本对照](package-provenance.json)。没有强杀 MySQL 服务或测试物理机掉电。

## 3. 争票与性能

三轮均为 1,000 个独立身份、100 工作线程、100 张票：每轮 **100 成功、900 SOLD_OUT、零系统错误、1,000 次尝试**。初始发起跨度分别 9.245/8.676/8.446 秒，收敛分别 10.182/9.605/9.386 秒。数据独立、无取消退款干扰，最终无超卖、重复资格及孤立记录。[三轮实测](contention.json)。100 线程与 1,000 用户分别记录。

最终包每阶段 20 工作线程、预热 60 秒、测量 300 秒；DATA-PERF 为 1,000 活动、3,000 场次、9,000 票档。客户端逐请求记录 HTTP 延迟与响应，P95 为最近秩法。查询与交易共 **308,682 条测量样本**，均成功，业务拒绝及系统错误为零。

| 接口 | 测量请求数 | P95（ms） |
| --- | ---: | ---: |
| 活动列表 | 55,019 | 48.606 |
| 活动详情 | 55,016 | 39.676 |
| 场次列表 | 55,017 | 40.974 |
| 票档列表 | 55,018 | 41.001 |
| 下单 | 44,305 | 70.906 |
| 模拟支付 | 44,307 | 69.325 |

四项查询达到 P95 ≤500ms，下单与支付达到 ≤1,000ms，系统错误率 <1%。支付后真实退款释放资格，退款施加负载但不混入上述延迟样本。样本数的轻微差异来自测量窗口边界，完整业务循环结束后全部 20 个交易票档重新对账无差异。最终查询阶段总耗时 360.650 秒，交易阶段 405.654 秒，交易总耗时包括采样保存与对账。

证据：[最终性能](performance.json)、[首轮性能](performance-initial.json)、[逐请求查询样本](query-samples.csv.gz)、[逐请求交易样本](trade-samples.csv.gz)、[独立重算](sample-verification.json)。保留首轮性能及慢对账耗时，不用两轮结果宣称严格优化前后对照。全部最终性能票档再次对账共 44.404 秒，无差异：[对账结果](optimized-reconciliation.json)、[优化后执行计划](optimized-reconcile-explain.json)。详细方法与环境见[阶段 06](../../../06_性能测试与优化.md)。
